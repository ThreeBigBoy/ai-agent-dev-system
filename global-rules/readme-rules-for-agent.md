# 项目根目录与 README 结构规范（通用）

本规则为**驱动所有项目开发的补充规范**，作为 `OpenSpec.md` 的补充，**复用于所有项目**。

以下为**与具体技术栈无关**的项目根目录与 README 结构约定，便于多项目一致、AI 与人工快速理解「哪里放什么」。标杆案例：`Proj01ShopifyTheme` 仓库根目录下的 `README.md`。

### 10.1 顶层目录划分原则

- **交付物根目录**：存放「会被部署、同步或构建产出」的代码/资源的**单一根目录**（如 Shopify 主题的 `theme-health-food/`、前端构建的 `dist/`、后端服务的 `src/` 等）。若平台有官方规定的目录数量与名称（如主题 7 文件夹），以平台规范为准；该目录内不混入设计文档、规范或一次性脚本。
- **design/**：设计侧文档与规则，**不参与构建或部署**。包含按项目/需求组织的文档（产品方案、需求说明书、技术方案、验收 Checklist、records 下的验收/反思记录）以及设计侧或领域相关的 `project-rules/` 补充。
- **openspec/**：本规范驱动的**规范与变更管理**根目录（见第二节），与 `project-rules/` 共同构成项目宪法与实现约束。
- **工具/一次性脚本目录**（可选）：按用途命名的独立目录（如「商家自助配置脚本」「数据迁移脚本」），内含脚本、配置与自有 README；**不参与主交付物构建或同步**，仅在需要时由人工或 CI 按说明执行。

根目录下除上述及版本控制、依赖管理（如 `package.json`、`node_modules/`）外，避免与交付物无关的顶层目录散落，以便 README 与目录一一对应。

### 10.2 README 结构建议

在项目根目录的 `README.md` 中，用**一级标题（`#`）** 与前面内容平级地列出上述每一类顶层目录（或主要入口），每块包含：

1. **标题**：目录名 + 简短角色说明（如「设计文档与项目规则（设计侧）」）。
2. **职责**：该目录存什么、是否参与构建/部署、与项目其他部分的关系。
3. **子目录或关键文件**： bullet 列举主要子目录或文件及用途。
4. **延伸**：若该目录下有独立 README，注明「详见该目录下 README.md」。

同一 README 内，**交付物根目录**、**design/**、**openspec/**、**工具/脚本目录** 等块应处于同一标题层级（如均为 `#`），便于扫读与后续项目复制。

### 10.3 通用模板（可复制到新项目）

```markdown

# [交付物名称] — 交付物根目录

本目录为 [平台/类型] 的 [部署/同步/构建] 根目录，[简短说明用途与入口命令或路径]。

[必要时的 2–3 条要点：如何部署、如何本地运行等。]
[若结构有单独规范，可写：] 目录结构及校验要点见 [链接或路径]。

---

# design/ — 设计文档与项目规则（设计侧）

design/ 存放 [领域] 相关的设计文档、产品说明与验收依据，不参与 [构建/部署]。

- design/documents/：按项目/需求组织的文档（产品方案、需求说明书、技术方案、验收 Checklist）；按变更组织的 `design/documents/[change-id]/records/` 下为验收记录、代码评审记录等，与需求同属该变更便于追溯。
- design/project-rules/：设计侧或领域规范补充，与根目录 project-rules/ 可配合使用。

便于产品/设计回溯与验收，以及 AI 或人工查阅需求与规范。

---

# openspec/ — 规范与变更管理（OpenSpec）

openspec/ 为本项目的 OpenSpec 规范驱动开发根目录。[1–2 句说明 project.md、AGENTS.md、changes/、specs/ 的角色。]

[2–4 条 bullet：project.md、AGENTS.md、changes/、specs/ 的用途与使用方式。]

开发与评审以 openspec/project.md 与 openspec/AGENTS.md 为准；[可选：常用 CLI 或链接]。

---

# [工具/脚本目录名]/ — [用途简述]

本目录提供 [一次性脚本/配置工具] 的 [用途]，[与哪份设计或规范对齐]；不参与 [构建/部署]。

- [子目录或关键文件]： [说明]。
- 使用方式： [入口命令或步骤]。详细 [前置条件、权限、行为] 见本目录下 README.md。
```

新项目可据此调整各块标题与内容，保持「交付物 / design / openspec / 工具目录」四类在 README 中平级、职责清晰，便于后续项目与 AI 一致遵守。
