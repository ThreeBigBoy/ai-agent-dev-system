> 
> **适用对象**:

## 关键设计原则

### 1. 统一 changes/ 目录

所有 change-id 相关文档（PRD、技术方案、评审记录、复盘）统一存放在 `design/documents/changes/[change-id]/` 下：
- `PRD-xxx.md` 直接放在 `[change-id]/` 下（change-id 的核心文档）
- `技术方案-xxx.md` 直接放在 `[change-id]/` 下（change-id 的核心文档）
- 所有评审记录、复盘放在 `[change-id]/records/` 下（过程记录）

### 2. 清晰的层级关系

```
design/documents/
├── changes/                    # change-id 相关（项目级）
│   └── [change-id]/
│       ├── PRD-xxx.md          # 核心文档
│       ├── 技术方案-xxx.md      # 核心文档
│       └── records/            # 过程记录
│
└── retrospectives/             # 跨 change-id（框架级）
    └── framework/
        └── 复盘-xxx.md         # 模式提炼
```

### 3. 区分核心文档 vs 过程记录

- **核心文档**（PRD、技术方案）：直接放在 `[change-id]/` 下
- **过程记录**（评审纪要、代码评审、验收、复盘）：放在 `[change-id]/records/` 下

### 4. 复盘 vs 执行偏差记录：术语严格区分

**重要**："复盘"和"执行偏差记录"是两个不同的术语，不可混用。

| 术语 | 定义 | 存放位置 | 产出时机 | 文档结构 |
|------|------|---------|---------|---------|
| **执行偏差记录** (Execution Deviation) | 执行过程中发现问题/偏差时的**即时记录** | `runtime-logs/execution-deviations/` | 问题发现时立即记录 | 自由格式，重在快速记录事实 |
| **复盘** (Retrospective) | 变更/阶段结束后的**系统性总结** | `design/documents/retrospectives/[level]/` | 变更归档后 | 必须含：目标→过程→根因→改进→模式沉淀 |

**关键区别**：
- 执行偏差记录 = 运行时审计，问"发现了什么偏差？"（即时事实记录）
- 复盘 = 方法论提炼，问"我们做得怎么样？为什么？下次如何更好？"（事后系统总结）

**禁止的做法**：
- 把 runtime-logs/execution-deviations/ 下的文档称为"复盘"
- 试图"先写执行偏差记录草稿，再迁移到 retrospectives/"——复盘一次性产出到正确位置，不需要草稿迁移

### 5. 复盘 3 级分离

| 复盘级别 | 存放位置 | 关注焦点 |
|---------|---------|---------|
| **change-id级** | `changes/[change-id]/records/` | 单个 change-id 执行过程 |
| **项目级** | `[项目]/retrospectives/[YYYY-MM]/` | 项目整体交付（跨 change-id）|
| **框架级** | `retrospectives/framework/[YYYY-QN]/` | 框架能力成长（跨项目模式提炼）|

## 与 OpenSpec 的对应关系

| OpenSpec 结构 | 本规范结构 | 说明 |
|--------------|-----------|------|
| `openspec/changes/[change-id]/proposal.md` | `design/documents/changes/[change-id]/PRD-xxx.md` | PRD 是 proposal 的详细展开 |
| `openspec/changes/[change-id]/tasks.md` | `openspec/changes/[change-id]/tasks.md` | 保持一致 |
| `openspec/changes/[change-id]/design.md` | `design/documents/changes/[change-id]/技术方案-xxx.md` | 技术方案是 design 的详细展开 |
| `openspec/changes/[change-id]/specs/` | `openspec/specs/[capability]/spec.md` | 归档后统一存放 |
