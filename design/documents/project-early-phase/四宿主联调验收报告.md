# 四宿主联调验收报告

## 1. 验收范围

本次验收覆盖以下四类宿主：

- Cursor 官方宿主
- VS Code 官方宿主 / GitHub Copilot
- Continue 插件
- OpenAI-Codex 插件

验收目标：

1. 宿主入口文件与 adapter 文档是否齐备
2. 治理内核与宿主策略是否一致
3. `agent_team_project` 是否能按宿主类型切换子 Agent 模型调度策略
4. 决策写入链路是否正常

## 2. 验收方法

本次验收分为三层：

1. **静态结构验收**
   - 检查 `.cursor/rules/`、`.github/agents/`、`platform-adapters/*/`、`agent_team_project/` 是否齐备
2. **本机可执行冒烟测试**
   - 通过 Python 导入和脚本执行验证：
     - `AGENT_HOST_TYPE` 分流是否生效
     - `write_decision` 是否能写入 `agent_decision.json` / `cursor_decision.json`
     - runtime Python 文件是否可通过 `py_compile`
3. **本机宿主配置核对**
   - 只读检查 `~/.cursor/mcp.json`

说明：

- 本次未进行 Cursor / VS Code / Continue / OpenAI-Codex 的真实 GUI 点击式端到端联调
- 因此“宿主内实时对话注入、按钮触发、插件 UI 行为”仍归类为**未做本机 GUI 实测**

### 4.1 宿主分流策略

通过导入 `agent_team_project/dynamic_agent_skill.py` 并设置 `AGENT_HOST_TYPE`，已验证：

- `cursor`：
  - 子 Agent 候选链路顺序为 `cursor_builtin -> api`
- `vscode`：
  - 子 Agent 候选链路顺序为 `cursor_builtin -> api`
- `continue`：
  - 子 Agent 候选链路顺序为 `api`
- `openai-codex`：
  - 子 Agent 候选链路顺序为 `api`

结论：

- 白名单宿主与第三方宿主的子 Agent 调度策略已按设计生效
