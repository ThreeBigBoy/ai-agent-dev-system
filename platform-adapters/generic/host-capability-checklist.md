## 宿主能力检查清单（host-capability-checklist）

在为某个第三方宿主编写 adapter 之前，可先用本清单评估其能力是否满足要求。  
当前 V2.2 明确优先覆盖的第三方宿主是：

- Continue
- OpenAI-Codex

### 1. 决策写入能力（decision_sink）

- [ ] 是否支持从 Agent 会话或扩展中，将结构化数据写入文件或外部服务？  
- [ ] 是否可以保证写入位置对运行后端可见？  
- [ ] 是否允许以 JSON 等可解析格式写入（例如 `agent_decision.json`）？

### 2. 运行触发能力（runtime_trigger）

- [ ] 宿主是否允许扩展或脚本触发外部进程 / 任务执行？  
- [ ] 是否可以通过命令、按钮或任务面板调用运行后端？  
- [ ] 是否有能力在触发时携带必要上下文（如当前工作区路径）？

### 3. 反馈桥接能力（feedback_bridge）

- [ ] 宿主是否提供将文本插入到 Agent 对话或输出区域的能力？  
- [ ] 如果不能直接写入，对「剪贴板 + 提示」这类降级方案是否可行？  
- [ ] 是否允许监听文件变化或接收来自运行后端的消息？

### 4. 工作区绑定能力（workspace_binding）

- [ ] 宿主是否有「当前工作区根目录」或「当前项目根路径」的概念？  
- [ ] 是否可以将该路径传递给运行后端（例如通过环境变量或命令参数）？  
- [ ] 是否支持多工作区场景下的清晰绑定策略？

### 5. 规则注入能力

- [ ] 是否支持为 Agent 会话配置「开场 instructions / system prompt」？  
- [ ] 是否可以引用或读取本仓库中的 Markdown 规则文件（如 `global-rules/*.md`、`agents/*.md`、`skills/*/SKILL.md`）？  
- [ ] 是否能为不同角色（主 Agent、前端 Agent 等）配置不同入口文件？

> 若多数勾选项为「否」，则需要在宿主本身或外围基础设施中先补足能力，再考虑嫁接 ai-agent-dev-system。
