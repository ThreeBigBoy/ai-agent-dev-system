## Cursor Feedback Bridge

本文件描述 ai-agent-dev-system 在 Cursor 宿主下的 **反馈桥接实现（feedback_bridge）**，用于把运行后端生成的执行反馈重新送回 Cursor Chat。

### 1. 定位

- 该机制属于 **Cursor adapter 的宿主接线层**，不属于治理规则本身。  
- 它实现的是宿主无关协议中的 `feedback_bridge`，在 Cursor 当前能力下采用了一种带人工粘贴步骤的降级方案。

### 2. 当前实现流程

在 Cursor 宿主下，反馈桥接通常按以下步骤工作：

1. 运行后端执行完成后，将反馈写入约定的反馈文件（例如 `agent_feedback.txt` 等，具体路径由运行后端约定）。  
2. 自定义 Cursor 插件监听反馈文件变化。  
3. 插件读取反馈内容后复制到系统剪贴板。  
4. 插件弹窗提示用户将反馈粘贴回 Chat。  
5. 用户在 Chat 中粘贴并发送后，主 Agent 根据反馈继续做「重新分工」或「结束闭环」的判断。

从运行后端到反馈文件、从反馈文件到剪贴板均可实现自动化；**从剪贴板到 Chat 的最后一步目前需要用户手动粘贴一次**。

### 3. 为什么采用该方案

原因不是治理层要求强行人工参与，而是：

- 目前 Cursor 尚未提供「由扩展程序直接向 Chat 注入消息」的稳定公共 API。  
- 为保证方案在 Cursor 可用版本上落地，只能退而求其次，通过「文件 + 剪贴板 + 人工粘贴」完成最后一步。

因此，该方案被视为在 Cursor 宿主能力限制下的一种**降级补丁**：

- 从治理角度看：只要运行结果可靠回到主 Agent 即可；方式可以替换。  
- 当 Cursor 将来提供直接写入 Chat 的能力时，可在本 adapter 中替换为更自动化的实现，而无需修改治理内核。

### 4. 边界与不变量

- 本机制 **不改变治理层规则**（OpenSpec、global-rules、agents、skills）。  
- 不改变主 Agent 的角色与决策逻辑。  
- 仅是 Cursor 下 `feedback_bridge` 的一个实现方式。  
- 与 VS Code 或其他宿主的反馈桥可以完全不同，只要满足「运行结果能回流到主 Agent」这一抽象要求。
